# 12 тижнів — трекер цілей

Односторінковий трекер за методикою "12 Week Year": вага, борг, капітал,
щотижневі/щоденні звички. Ванільний HTML/CSS/JS, без фреймворків, один файл
`body.html`. Синхронізація — Google Apps Script backend (`tracker-backend.gs`)
+ localStorage як кеш і офлайн-фолбек.

- Живий сайт: https://kazmirchuk96.github.io/tracker/
- Репозиторій: kazmirchuk96/tracker, гілка `main`, GitHub Pages з кореня
- **Зараз у репозиторії лежить лише зібраний `index.html`.** Вихідний
  `body.html` і тести туди ще не додані — перше, що варто зробити.

## Критичне правило: деплой лише за прямою командою

**НІКОЛИ не публікуй у GitHub (не роби `git push`) без явного "заливай"/
"залий" від користувача в тому ж повідомленні.** Показуй готовий результат
локально/у прев'ю й чекай на підтвердження. Це правило дотримувалось
буквально в кожному з ~55 білдів цього проєкту — жодного випадку, коли
publish стався без прямої команди.

## Як збирається фінальний файл

`body.html` — це вміст `<body>...</body>`, БЕЗ обгортки `<html><head>`.
Перед показом користувачу чи публікацією він загортається в мінімальний
HTML-шаблон (`<!DOCTYPE html>`, viewport/apple-mobile-web-app мета-теги,
`<style>html,body{margin:0;padding:0;background:#0F0E0A;}</style>`) і
зберігається як самостійний `index.html`. Сам `body.html` НЕ є валідним
автономним документом — не відкривай його напряму в браузері без обгортки.

## Тестова дисципліна (ВАЖЛИВО — тести цієї сесії втрачені)

Попередня робота (у Claude.ai) використовувала jsdom-тести (Node.js,
`new JSDOM(page, {runScripts:'dangerously', beforeParse: мокати
localStorage/Date/fetch/clientWidth})`) — по одному файлу на кожен раунд
фідбека, ~10-25 перевірок кожен, разом 257 перевірок у 11 файлах. **Ці файли
існували лише в тимчасовій пісочниці Claude.ai й не збереглися** — фактично
код тепер БЕЗ автоматизованих тестів. Перше, що варто зробити в новій сесії:
попросити Claude Code відновити подібний тестовий каркас (jsdom + мок
localStorage/Date/fetch) і поступово нарощувати покриття для нових змін.

Обов'язково перевіряй КОЖНУ зміну автоматизованим тестом, а не лише візуально
— цей застосунок кілька разів ламався саме там, де тестів не було (див.
нижче "Засвоєні уроки").

## Засвоєні уроки (щоб не наступати на ті самі граблі)

- **Рендер повний, не диференційний**: `render()` перебудовує весь DOM з нуля
  на кожну дію. Наслідки: (1) CSS-анімації прив'язані до `[aria-checked]`
  чи подібних універсальних селекторів програються на ВСІХ елементах, що
  підпадають під умову, при КОЖНОМУ рендері, не лише на щойно зміненому —
  рішення: власний клас на кшталт `just-toggled`, що ставиться лише
  потрібному елементу й скидається наприкінці рендеру; (2) старі посилання
  на DOM-вузли з тестів стають "мертвими" одразу після кліку, що викликав
  render() — завжди перезапитуй вузол після дії, ніколи не тримай посилання
  через межу рендеру.
- **Модалки й z-index**: якщо одна модалка (підтвердження) може відкриватись
  ПОВЕРХ іншої (налаштування), їхні z-index НЕ можуть бути однаковими —
  при рівному z-index порядок промальовки визначає позиція в DOM, не порядок
  відкриття через JS. Цей клас багів невидимий для jsdom-тестів (немає
  візуального рендеру) — тримай це на увазі, коли додаєш вкладені модалки.
- **`<input type="number">` вимагає крапку** як десятковий роздільник
  незалежно від локалі пристрою. На iOS з українською розкладкою екранна
  клавіатура показує кому — браузер її відкидає. Для полів із дробовими
  значеннями використовуй `type="text" inputmode="decimal"` і розбирай
  кому/крапку сам (`parseFloat(v.replace(',', '.'))`).
- **Тап-ціль мінімум 44px** (`--tap`) для звичайних кнопок; є менший токен
  `--tap-sm` (32px) спеціально для компактних чекбоксів дій — застосовано
  за прямим проханням користувача, не застосовуй його деінде без такого ж
  явного запиту.
- **Фіксований розмір, не респонсивний**, для дрібних елементів у сітці
  (квадратики днів): `width:100%` + `aspect-ratio:1` + `min-height` може
  дати прямокутник замість квадрата, якщо колонка вужча за min-height.
  Однакові фіксовані `width`/`height` — надійніше.
- **Кольорова семантика**: зелений (`--accent`) = виконано/успіх/сьогодні.
  Був експеримент із другим "брендовим" кораловим акцентом для CTA/сьогодні
  — користувач послідовно просив прибрати його з кожного місця, де він
  з'являвся, бо читається як заперечення. Тримайся одного акценту, поки не
  попросять інакше.
- **Токени, не літерали** в CSS — уся шкала кольорів/відступів/радіусів
  визначена у `:root`. Нове значення — новий токен із коментарем-обґрунтуванням,
  не магічне число в правилі.
- **Підтвердження для будь-якої незворотної дії**, навіть коли "нема чого
  втрачати" (наприклад, видалення порожньої дії) — консистентність
  важливіша за економію одного кліку.
