# Тести трекера

Запуск:

```bash
npm install   # один раз, ставить jsdom
npm test
```

## Підхід

Чорна скринька через jsdom, а не виклик внутрішніх функцій напряму: логіка в
`body.html` захована в одному IIFE й нічого не експортує на `window` — і так
і мало лишитись, щоб тест не тримався за деталі реалізації, а перевіряв те
саме, що бачить користувач (клік по чекбоксу, текст поля, значення в
localStorage).

`tests/helpers/tracker.js` — `mountTracker()` піднімає `body.html` у jsdom з
підміненими `Date` (фіксований "зараз"), `fetch` (вимкнено за замовчуванням,
щоб випадковий безумовний виклик впав тестом) і `clientWidth` (jsdom не
рахує layout, інакше графіки завжди бачили б ширину 0). `seed` заздалегідь
кладе дані в `localStorage` під тими ж ключами (`tracker:week:1` тощо), що і
сама сторінка — так само, як якби користувач відкрив її вдруге.

## Що вже покрито

Кожен файл — регрес на конкретний баг із git-історії/CLAUDE.md, не абстрактна
перевірка "воно взагалі працює":

- `smoke.test.js` — базовий рендер без падіння в error-екран.
- `decimal-input.test.js` — кома як десятковий роздільник у полі ваги (iOS).
- `checkbox-animation-scope.test.js` — анімація `just-toggled` лише на
  щойно клікнутому чекбоксі, не на всіх зі збіжним станом.
- `modal-zindex.test.js` — модалка підтвердження перекриває модалку
  налаштувань (статична перевірка z-index — цей клас багів невидимий для
  jsdom без layout/composited-шарів, тому тест саме про верстку, не про
  візуальний рендер).
- `sync-race.test.js` — тап під час фонової синхронізації не відкочується
  застарілою відповіддю сервера (`editedDuringSync`).
- `import-sanitize.test.js` — імпорт JSON з биженою структурою (`weight:
  "abc"`, масив не з 7 елементів) не протікає в стан як сміття.

## Як перевірено, що тести не проходять "про людське око"

Перед комітом кожен новий тест тимчасово ламався в самому `body.html`
(відкочування пізніше `git checkout`), щоб переконатись, що асерт справді
падає на зламаному коді, а не завжди зелений незалежно від логіки.

## Чого ще бракує

Це стартовий каркас, не повне покриття. Попередній набір (Claude.ai,
257 перевірок у 11 файлах) охоплював значно ширше — графіки, close-цілей
(`autoCloseCheck`), кастомні тактики, CSV/JSON експорт, клавіатурну
навігацію в модалках. Додавай тест на кожну наступну правку, а не лише
перевіряй візуально — саме відсутність тестів кілька разів ламала цей
застосунок непомітно (див. CLAUDE.md, "Засвоєні уроки").
